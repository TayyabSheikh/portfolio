Selected work 2022–2026

Results tell you a model works. Structure tells you when it won’t.

Which is why I work on the structure: how a representation arranges itself, what that arrangement survives, and where it gives out once the data shifts underneath it. A different hospital, a different scanner, a different population. Lately I have been asking the same of language models in production.

01 · Master’s thesis Bamberg, 2025

What survives the move between hospitals

My thesis at the Chair of Explainable Machine Learning asked a narrow question with a wide blast radius. When a medical imaging model meets data from a hospital it was never trained on, which part of what it learned still holds?

I benchmarked out-of-distribution generalisation strategies across large-scale medical datasets, comparing how different representation geometries behave when the scanner, the acquisition protocol and the patient population all change at once.

MedAugmix came out of that work: a targeted augmentation strategy that improves generalisation by six percentage points across hospitals and demographics. It is not a new architecture. It is a different arrangement of what the model already sees.

Supervised byProf. Dr. Christian Ledig

02 · Masoona Consulting Nuremberg, 2025

The conversation is new. The process is not.

A driving licence intake system in which the language model never invents the workflow. The steps, the states and the transitions are defined in BPMN and executed by Flowable. A custom Model Context Protocol server lets a conversation trigger them, and nothing else.

The server exposes a fixed set of case operations rather than a database. A request with no corresponding transition has nothing to call, so the failure mode is a conversation that cannot proceed, not a case sitting in a state the process never defined.

I owned the delivery end to end: TypeScript and React, Microsoft Entra ID for authentication, the Flowable REST integration behind it, then Docker, Nginx and CI/CD. 03 · Eva Personal project

The model explains, it does not compute

An iOS app that reads Apple Health data over the local network and sends it nowhere else. Two Gemma models run through Ollama on a machine at home: one for reasoning and tool calls, one for fast replies.

A language model asked to produce a number will eventually produce a confident wrong one, and a health figure is exactly the kind of number somebody acts on without checking it.

So the split is the whole design. The engine owns the arithmetic, the models own the language, and neither is asked to do the other one’s job.
